# Sonic 애니메이션 뷰어 PRD

> 모든 커밋 메시지는 반드시 한글로 작성한다.

## 1. 프로젝트 목표

Pico2D를 사용해 `sonic-sprite.png`에 포함된 소닉의 동작을 순서대로 보여주는 애니메이션 뷰어를 제작한다. 사용자는 별도의 조작 없이 모든 동작을 충분히 큰 화면으로 확인할 수 있어야 한다.

- 동작별 5회 반복과 동작 사이 1.0초 대기
- 전체 동작의 순차 및 무한 반복 재생
- 스프라이트 확대와 화면 중앙 정렬

### 3.2 제외 범위

- 사용자의 동작 선택 또는 재생 속도 변경
- 배경음악 및 효과음
- 메뉴, 점수 및 게임 플레이 기능
- 스프라이트 이미지 편집
- 제목, 제작자 표기 및 장식 이미지 재생

## 4. 재생 대상

제목 영역과 크레딧·장식 영역을 제외하고, 캐릭터 영역을 10개 동작과 총 76개 프레임으로 구분한다. 아래 `y` 범위는 이미지의 왼쪽 위를 원점으로 측정했으며 양 끝값을 포함한다.

| ID | 식별명 | 상단 기준 y 범위 | 프레임 수 | 수평 이동 속도 |
| --- | --- | ---: | ---: | ---: |
| A01 | 대기·자세 전환 | 39~77 | 11 | 정지 |
| A02 | 걷기 | 79~117 | 12 | 60 픽셀/초 |
| A03 | 대시·공격 동작 | 121~163 | 6 | 180 픽셀/초 |
| A04 | 회전 전환 | 167~199 | 9 | 정지 |
| A05 | 공 회전 | 206~232 | 6 | 150 픽셀/초 |
| A06 | 고속 달리기 A | 238~273 | 6 | 130 픽셀/초 |
| A07 | 고속 달리기 B | 283~317 | 6 | 150 픽셀/초 |
| A08 | 방향 전환·피격 동작 | 326~370 | 8 | 정지 |
| A09 | 달리기 순환 | 377~416 | 8 | 115 픽셀/초 |
| A10 | 세리머니·제스처 | 426~468 | 4 | 정지 |

- 재생 순서는 `A01`부터 `A10`까지로 고정한다.
- 각 행의 프레임은 왼쪽에서 오른쪽 순서로 등록한다.
- 식별명은 개발 편의를 위한 이름이며 ID와 프레임 범위를 판정 기준으로 사용한다.
- 한 장짜리 자세는 별도 애니메이션으로 만들지 않고 해당 행의 프레임으로 처리한다.
- 이동 속도는 화면 좌표 기준이며, 양수는 오른쪽 방향을 뜻한다. 프레임이 재생되는 동안 해당 속도로 캐릭터를 수평 이동한다.
- 이동 동작은 화면 가장자리에서 캐릭터가 잘리지 않도록 가시 영역의 오른쪽 끝에 도달하면 왼쪽 안전 위치에서 이어서 이동한다. 동작이 끝난 뒤에도 위치를 유지한다.

## 5. 기능 요구사항

### FR-01. 프로그램 시작

- 1200 × 800 크기의 Pico2D 캔버스를 연다.
- 실행 위치와 관계없이 실행 파일이 있는 폴더에서 `sonic-sprite.png`를 찾는다.
- 이미지를 불러오지 못하면 원인을 알 수 있는 오류 메시지를 출력하고 종료한다.

### FR-02. 프레임 데이터

- 각 동작은 ID, 이름 및 프레임 목록을 가진다.
- 각 프레임은 `x`, `y`, `width`, `height` 및 기준점으로 정의한다.
- 캐릭터 픽셀이 잘리거나 이웃 프레임이 포함되지 않도록 프레임 영역을 지정한다.
- 코드에 저장하는 좌표는 Pico2D의 왼쪽 아래 원점을 기준으로 한다.
- 이미지 상단 기준 좌표는 다음 식으로 변환한다.

```text
pico_y = 525 - (top_y + height)
```

### FR-03. 프레임 재생

- 현재 동작의 첫 프레임부터 마지막 프레임까지 순서대로 표시한다.
- 모든 동작에 0.1초의 고정 프레임 간격을 적용한다.
- 프레임 전환은 경과 시간을 기준으로 처리한다.
- 이동 속도가 지정된 동작은 같은 경과 시간에 따라 수평 위치도 갱신한다.
- 마지막 프레임 다음에는 첫 프레임으로 돌아가며, 이때 1회 재생으로 계산한다.

### FR-04. 반복 및 동작 전환

- 각 동작을 정확히 5회 재생한다.
- 다섯 번째 재생이 끝나면 마지막 프레임을 유지한 채 1.0초간 대기한다.
- 대기가 끝나면 반복 횟수와 프레임 번호를 초기화하고 다음 동작으로 전환한다.
- `A10`까지 끝나면 `A01`부터 다시 재생한다.

| 상태 | 처리 내용 |
| --- | --- |
| `PLAYING` | 프레임을 재생하고 완료 횟수를 계산한다. |
| `PAUSED` | 다섯 번째 재생의 마지막 프레임을 1.0초간 유지한다. |
| `NEXT` | 다음 동작을 선택하고 재생 상태를 초기화한다. |

### FR-05. 화면 출력

- 모든 프레임에 동일한 정수 확대 배율을 적용한다.
- 확대 배율은 기존 설정의 절반으로 낮춘다. 가장 큰 프레임이 캔버스 가로·세로의 40%를 넘지 않는 최대 정수 배율을 적용한다.
- 프레임의 하단 중앙을 기준점으로 사용한다. 세로 기준선은 고정하고 수평 위치는 동작의 이동 속도에 따라 갱신한다.
- 정지 동작은 현재 수평 위치에서 재생하고, 이동 동작은 프레임 재생과 함께 수평으로 이동한다.
- 이동 중 캐릭터 전체가 화면 안에 보이도록 이동 범위를 제한하고, 오른쪽 경계에서는 왼쪽 안전 위치로 순환한다.
- 최대 높이 프레임의 세로 중심이 캔버스 중앙에 오도록 기준선의 y 좌표를 계산한다.
- 원본 비율을 유지하고 스프라이트가 화면 밖으로 잘리지 않게 한다.
- 투명 영역과 캐릭터 윤곽을 구분하기 쉬운 단색 배경을 사용한다.

### FR-06. 종료 처리

- 창 닫기 이벤트 또는 `Esc` 입력 시 메인 루프를 종료한다.
- 프로그램 종료 전에 Pico2D 캔버스를 닫는다.
- 실행 중 예외가 발생하더라도 가능한 경우 캔버스 정리 작업을 수행한다.

## 6. 구현 기준

### 6.1 데이터 구조

```python
ANIMATIONS = [
    {
        'id': 'A01',
        'name': '대기·자세 전환',
        'movement_speed': 0.0,
        'frames': [
            {'rect': (x, y, width, height), 'anchor': (anchor_x, anchor_y)},
        ],
    },
]
```

### 6.2 메인 루프

메인 루프는 다음 순서를 유지한다.

1. 이벤트 처리
2. 경과 시간 계산
3. 애니메이션 상태 갱신
4. 화면 그리기
5. 캔버스 갱신

### 6.3 구현 원칙

- 프레임 출력, 상태 갱신 및 이벤트 처리를 함수로 분리한다.
- 프레임 간격과 동작 사이 대기는 `delay()`가 아닌 시간 비교로 처리한다.
- 모든 스프라이트 좌표는 한곳에서 관리한다.
- 동일한 출력 및 상태 처리 코드를 반복해서 작성하지 않는다.
- Pico2D 외의 추가 라이브러리에 의존하지 않는다.
